# Design-System Catalog

Use this catalog only when a repository has a rendered UI and no established
design system is evident. Verify current project documentation before
recommending a system. This file is a selection aid; it is not the generated
project design document.

Source catalog: [awesome-design-md](https://github.com/VoltAgent/awesome-design-md)

| System | Good fit | Notes |
|---|---|---|
| Material Design 3 | Android and cross-platform apps | Platform-oriented components and tokens |
| Apple Human Interface Guidelines | Native Apple platforms | Platform conventions and system components |
| Fluent 2 | Windows and enterprise applications | Microsoft ecosystem and accessibility guidance |
| Carbon | Enterprise, data-heavy interfaces | IBM design system and component guidance |
| Polaris | Shopify administration and commerce | Commerce workflows and admin patterns |
| Atlassian Design System | Collaboration and project-management tools | Atlassian product patterns |
| Primer | Developer tools and GitHub-integrated products | GitHub's design system |
| Lightning Design System | Salesforce applications | Salesforce platform components |
| Adobe Spectrum | Creative and professional tools | Adobe platform patterns |
| Ant Design | Enterprise administration interfaces | Broad component library |
| Radix UI / shadcn/ui | React applications | Composable primitives; verify project adoption and accessibility |
| Vercel Geist | Developer tools and technical products | Vercel's interface system |
| PatternFly | Operations and infrastructure consoles | Red Hat's enterprise UI system |

Choose based on the actual platform, existing stack, accessibility needs,
brand constraints, and maintainability. Do not prescribe a default when those
factors or the product decision are unknown.
